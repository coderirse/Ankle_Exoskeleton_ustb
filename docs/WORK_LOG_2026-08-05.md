## 1. 今天修复的问题（按发现顺序）

### ① udev 规则失效（编码器端口漂移）
- 编码器换到 hub 端口 2.4，`99-ankle.rules` 已更新，`/dev/ankle_encoder` 恢复
- launch 里写死的 `/dev/ttyUSB2`（其实是力传感器！）改回 `/dev/ankle_encoder`

### ② 串口字节污染步态序列（serial_sendCommand_node）
- 非法字节（线路噪声）会更新去重基准 `last_raw_byte`，导致心跳重发被误判为新跳变 → `resetToStart` 打断步态
- 修复：非 0x41~0x45 字节只告警、不更新基准、不发布

### ③ 35kg 急停事故（上午第一次试走）
- 搬动假肢误触 0x41~0x43 序列 → 蹬地助力对静止的脚硬拉 → 50ms 内力从 20 冲到 37.45kg → 急停锁存（保护按设计工作）
- 新增 `drive_force_ceil`（默认 22kg）：驱动阶段张力超上限禁止继续收线（只许放线），软限/硬限来不及反应的空白被填上

### ④ PRE_TORQUE_MODE 主循环无分支
- 0x42 后电机保持上一条指令（可能无控收线）→ 先改零速，后发现这杀掉了 0x42~0x43 窗口的松弛回收 → 最终改为与 0x41 阶段相同的**两档力门控预张紧**（力<1kg 全速 300°/s 抢收，1~2kg 慢速 60°/s，≥2kg 停）

### ⑤ CAN 接收线程持锁饿死主循环（"电机没反应"的元凶之一）
- `receive_func` 持 `can_mutex` 做 10ms 阻塞接收并紧凑循环，主线程发送几乎永远抢不到锁 → 主循环 200Hz 跌至 2.5Hz（gdb 三次采样坐实）
- 修复：非阻塞接收 + 无数据时 `usleep(1000)`

### ⑥ 力→扭矩系数 5 倍错误（"助力太弱"的主因）
- 老程序（ROS1，跑步机验证过）：`Force(N) × 0.12m` 力臂
- 新程序：`/Force` 单位是 **kg**（老的是 N），却用 `×6.0` —— 折算 1.18 vs 6.0 Nm/kg，差 5 倍
- 后果：目标 23Nm 时老系统拉 ~20kg 线张力，新系统拉到 ~4kg 就以为达标 → 完全没有助力感
- 修复：`torque_per_force` 6.0 → **1.18**（踝侧结构未变，力臂沿用 0.12m）

### ⑦ 摆动相放线方向门控永不成立（"不跟脚/被线拽"的主因）
- 原逻辑 `theta_d < theta_m`（编码器位置门控）在当前安装方向下永不满足 → 实测摆动相净放线≈0°，线上挂 10~16kg 拖拽脚
- 修复：纯力比例放线（`swing_release_gain=40` °/s per kg），线紧就放、线松自停，不依赖方向假设。**实测摆动相张力 10-16kg → 3-5kg**

### ⑧ 驱动器轮廓加减速未设置（"电机太慢/幅度小"的核心）
- 卓誉驱动器 PV 模式按 0x6083/0x6084 斜坡规划速度，控制节点从未设置，默认值温柔 → 指令 600°/s 电机慢爬
- `motor_remote.py`（调试遥控器）里明确设置了 50000 —— 移植时丢失
- 修复：`can_init()` 显式写入 6083/6084 = 50000
- 附带确认：~~该驱动器 CAN 协议只写无应答~~（**2026-08-06 更正：SDO 可读，应答 COB-ID 是 0x5D3 不是 0x583**，详见 WORK_LOG_2026-08-06）

### ⑨ 力传感器断流无防护（下午险些绷断线）
- 力传感器通信中断时 `/Force` 无消息，控制端力恒为 0 → 初始化力控误判"线松"不停收线，且 35kg 急停因读不到力而失效 → **持续收紧险断鲍登线**
- 修复：力传感器看门狗——0.5s 无更新立即锁停报警（启动宽限 5s），初始化与主循环均生效，锁存后需重启

### ⑩ 其他
- 编码器安全限位 45° → 75°（实测正常步态跖屈可达 -51°，原值误触发归零并关闭节点）
- 指令顺序错误不再触发归零（归零目标编码器值在穿戴行走时永远回不去，会卡死主循环），改为回 STAND 等下一个 0x41 自动重同步
- 新增手动确认闸门：初始化完成后需在终端按 Enter 才进主循环（读 `/dev/tty`，ros2 launch 子进程 stdin 是管道）；Enter 后丢弃积压指令 200ms + 重置顺序校验
- 终端可读状态行（1Hz）：模式中文名 + 力 + 实时速度指令；编码器节点 200Hz 刷屏打印已删除
