## 1. 今日进展

### 端口持久化映射
为避免拓展坞重排导致 `/dev/ttyUSB*` 变化，新增 udev 规则固定符号链接：

| 符号链接 | 当前指向 | 设备 |
|---------|---------|------|
| `/dev/ankle_encoder` | `/dev/ttyUSB0` | 编码器 (Modbus RTU 9600) |
| `/dev/ankle_switch` | `/dev/ttyUSB1` | 足底开关 (UART 9600) |
| `/dev/ankle_force` | `/dev/ttyUSB2` | 力传感器 (Modbus RTU 19200) |
| `/dev/ankle_can` | `bus/usb/001/008` | CANalyst-II (04d8:0053) |

规则文件：`scripts/99-ankle.rules`，安装命令：
```bash
sudo cp scripts/99-ankle.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
sudo udevadm trigger
```

### 控制链路 C++ 化完成
- 删除 Python 控制代码：`scripts/assist_controller.py`、`scripts/can_bridge.py`、`scripts/switch_node.py`、`src/can_ankle/scripts/can_bridge.py`、`src/can_ankle/src/can_ankle_node.cpp`
- `can_ankle_node.h` 改用 `libcontrolcan.so` 原生 VCI API（`VCI_OpenDevice/InitCAN/StartCAN/Transmit/Receive`）
- `can_init()` 集成 `usbreset` 解决 `libusb_set_configuration` 报 busy 的问题
- 修复 `can_init()` 调用 `can_send()` 导致的递归锁死锁（`std::mutex` → `std::recursive_mutex`）
- `pthread_create` 启动 CAN 接收线程并 `pthread_detach`
- `signalHandler` 中调用 `can_close()` 释放 CAN 设备

### 控制节点参数化
`can_ankleControl_node.cpp` 全部改为 ROS 参数：
- `control_mode`, `user_weight`, `force_limit`
- `torque_per_force`, `motor_dir`
- `preload_speed`, `preload_force`, `preload_timeout`
- `max_speed`

新增统一速度指令 `send_speed(double deg_s)`，通过 SDO `0x60FF` 下发，`uu/s = deg/s × 600`。

### Launch / 启动脚本
- `start_node.launch.py`：去掉 `xterm` 依赖，启动 4 个节点，控制节点延迟 2s 启动等力传感器稳定
- `scripts/start_all.sh`：一键启动全链路
- `scripts/stop_all.sh`：一键停止

### 全链路手动按钮实测 ✅
启动：`ros2 launch can_ankle start_node.launch.py`

足底开关按下后状态机正确切换：
- `0x41` → `TORQUE_MODE`（存储支撑相起始电机角度）
- `0x42` → `PRE_TORQUE_MODE`（坡度=0）
- `0x43` → `TORQUE_DRIVE_MODE`（计算 drive time / peak torque）
- `0x44` → `VELOCITY_MODE`（摆动相）

实测看到电机按按钮助力，力传感器读数随电机动作变化（4.98 → -0.78 → 3.54 等）。

## 2. 参数速查

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `control_mode` | 1 | 1: 自适应扭矩曲线；2: 定参数扭矩曲线 |
| `user_weight` | 60.0 | 用户体重 kg，影响峰值扭矩 |
| `force_limit` | 5.0 | 力限值（/Force 尺度），超限立即停电机 |
| `torque_per_force` | 6.0 | /Force 单位 → Nm 换算（台架杠杆比） |
| `motor_dir` | 1.0 | +1 收线拉紧，-1 放线 |
| `preload_speed` | 10.0 | 开机预紧爬速 deg/s |
| `preload_force` | 0.2 | 预紧目标力（线绷直判据） |
| `preload_timeout` | 4.0 | 预紧超时 s |
| `max_speed` | 180.0 | 速度限幅 deg/s |

调参示例：
```bash
ros2 run can_ankle can_ankleControl_node --ros-args \
  -p force_limit:=3.0 -p max_speed:=100.0
```

## 3. 启动方式

推荐：
```bash
ros2 launch can_ankle start_node.launch.py
```

或脚本：
```bash
bash scripts/start_all.sh
bash scripts/stop_all.sh --auto
```

完整系统需启动的节点：
1. `serial_ForceSensor_node` — 力传感器
2. `serial_encoder_node` — 编码器
3. `serial_sendCommand_node` — 足底开关
4. `can_ankleControl_node` — 主控制

如需 IMU 坡度补偿，再启动：
```bash
ros2 launch fdilink_ahrs ahrs_data.launch.py
```

## 4. 已知问题 / 下一步

- **台架不松线**：`0x44` 摆动相依赖编码器反馈 `theta_m > theta_d` 才发反转速度；台架编码器与电机未机械联动，所以不松线。上脚穿戴后应正常。
- **SIGINT 崩溃**：收到 Ctrl+C 时 `serial_ForceSensor_node` / `serial_encoder_node` 偶发 `RCLError: failed to create guard condition`，为 ROS2 多节点同时 shutdown 的已知现象，不影响运行期间功能。
- **IMU 坡度补偿**：代码已订阅 `/imu` 和 `/system_speed`，但 `initializeSlopeFile()` 被注释，未启用。
- **PDO 主动上报**：CAN 接收线程已启动，但电机未配置 PDO 周期上报，当前 `Output_TorqueValue`/`Output_VelocityValue` 为 0；如需电机反馈需配置 COB-ID 映射。
- **鲍登线打滑**：预紧和 DRIVE 都依赖线不打滑，上线后需观察。
