### 力传感器"假死"真凶
- 现象：D056屏幕亮有数值，但任何波特率/站号/校验探测全无响应
- **原因：端口竞争** — ROS力传感器节点一直在轮询并flush输入缓冲，独立探测脚本的响应全被抢读
- 教训：**探测串口设备前必须先停掉占用该端口的ROS节点**
- 教训2：拓展坞重排端口，switch_node.py里写的ttyACM0是错的（那是IMU）

### 电机调试（电机-鲍登线-力传感器台架）
- **方向**：带线实测确认 `motor_dir=+1`=收线拉紧（空载目测判断不可靠，必须看力读数）
- **速度**：增益3.0→20.0，限幅50→400 deg/s（原参数慢到几乎不动）
- **力标定**：手绷紧线 D056显示0.4-0.5kg ↔ /Force读数0.27-0.39（×0.01系数基本对应）
- **力保护**：`|force| ≥ 2.0` → 立即停电机回STAND，报警锁存，恢复后自动解除。实测DRIVE拉到2.0瞬间停机，后续DRIVE全闭锁 ✅
- **开机预紧标定（新功能）**：上电后电机10 deg/s慢爬收线，直到`|force| ≥ 0.2`（鲍登线绷直）→ 停 → 待机。超时4s报警
  - 坑：30 deg/s预紧会过冲（停于0.39读数但张力惯性冲到2.1），**降到10 deg/s后过冲仅0.4**
  - 力反馈链路延迟~150ms（20Hz Modbus轮询+发布），高速收线必过冲

### 验证过的完整链路
```
踩开关 → 0x41/42/43/44 → 状态机 → DRIVE(峰值360deg/s) → 张力0.6→2.0 → 力保护停机 ✅
```

## 3. 启动方式（改进版）

```bash
# T1: CAN桥 (setsid防误杀)
sudo setsid python3 scripts/can_bridge.py

# T2: 传感器+开关
source /opt/ros/humble/setup.bash && source install/setup.bash
python3 scripts/switch_node.py &
ros2 run can_ankle serial_encoder_node &
ros2 run can_ankle serial_ForceSensor_node --ros-args -p debug:=false &

# T3: 助力控制器（开机自动预紧）
python3 scripts/assist_controller.py
```

注意：后台启动ROS节点要用`setsid`+输出重定向到文件，否则终端工具超时会把进程组一起杀掉（今天桥接器就这么死的）。

## 4. 已知问题/下一步

- **力闭环**：DRIVE目前一刀切停机，要改成调转速维持目标张力（老C++的PID `pid.compute(target_torque, SensorTorque, dt)` 就是干这个的）
- **自适应步态**：老C++根据步速调峰值扭矩(体重×0.3+补偿)和PID参数(Kp=20~60)，Python版目前是固定peak=18Nm
- **编码器归位**：SWING用编码器反馈，但台架上编码器不在电机传动链上，测不到；上线穿戴后再调
- **鲍登线会滑**：手绷紧后线会慢慢滑脱，预紧功能依赖线不打滑
- **rqt_plot**：`rqt_plot /target_torque/data /motor_speed/data /gait_mode/data /force_scaled/data`
