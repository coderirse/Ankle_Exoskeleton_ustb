## 2. 架构演进（重要！）

### 2.1 最终可用方案：TCP 桥 + ROS2 Python 双进程

```
终端1（sudo）: can_bridge_final.py  ──── TCP :9876 ────  终端3（用户）: ros2_final.py
  │                                                          │
  └─ python-can → CANalyst-II → 电机                         ├─ ROS2 topic 发布/订阅
                                                             └─ 自动/开关触发步态循环
终端2（用户）: ROS2 传感器节点（编码器、力传感器）
终端4（用户）: rqt_plot 实时曲线
```

**为什么必须双进程？**
- `fork()` / `posix_spawn` / `subprocess.Popen` 都会破坏 ROS2 DDS 中间件
- C++ 节点的 `Init_Can()` 创建子进程后，`rclcpp::init` 会崩溃（"context argument is null"）
- 即使把子进程移到 `rclcpp::init` 之前，ROS2 topic 仍然不可见
- **唯一解决方案：CAN 通信和 ROS2 通信必须跑在两个独立进程中**

### 2.2 C++ 节点状态

所有 9 个 C++ 文件都能编译通过，但由于 fork/DDS 问题：
- `can_ankleControl_node`：编译通过，`rclcpp::init` 缺失（被脚本误删）、订阅全被删，修复后 ROS2 topic 不可见
- `can_test_node`：已验证电机转动（用旧的子进程方式），但 ROS2 不可见
- 传感器节点（`serial_encoder_node`、`serial_ForceSensor_node`）：ROS2 正常，**不创建子进程所以没受影响**
- **结论：需要 CAN 的节点用 Python TCP 桥方案，纯传感器的节点继续用 C++**

## 6. 脚底开关协议

脚底开关通过串口（9600bps）发送单字节触发步态：

| 字节 | 含义 | 触发动作 |
|------|------|----------|
| `0x41` | 脚跟着地 | TORQUE_MODE — 记录起始位置 |
| `0x42` | 支撑初期结束 | PRE_TORQUE_MODE — 存储坡度，计算峰值扭矩 |
| `0x43` | 全脚支撑 | TORQUE_DRIVE_MODE — 执行余弦助力曲线 |
| `0x44` | 脚趾离地 | VELOCITY_MODE — 摆动相归位 |

**读取节点**：`serial_sendCommand_node`（C++），读取串口、检查顺序、计算相时间，发布到：
- `/command_topic` (UInt8)
- `/one_support_time`、`/two_support_time`、`/three_support_time`、`/swing_time` (Float64)

## 7. CAN 通信协议细节

### 电机参数
- CANopen Node ID：0x53 (83)
- SDO 发送 COB-ID：0x600 + 0x53 = 0x653
- SDO 回复 COB-ID：0x580 + 0x53 = 0x5D3
- 心跳 COB-ID：0x700 + 0x53 = 0x753

### SDO 命令格式
```
[Cmd] [IndexLow] [IndexHigh] [Sub] [Data...]
```

| 命令 | 数据长度 | 含义 |
|------|----------|------|
| 0x2F | 1 byte | 写 1 字节 |
| 0x2B | 2 bytes | 写 2 字节 |
| 0x23 | 4 bytes | 写 4 字节 |

### 常用 SDO 写入

| 对象 | Index/Sub | 值 | 含义 |
|------|-----------|-----|------|
| 模式选择 | 0x6060/00 | 0x03 | Profile Velocity 模式 |
| 控制字 | 0x6040/00 | 0x06 | Shutdown |
| 控制字 | 0x6040/00 | 0x07 | Switch On |
| 控制字 | 0x6040/00 | 0x0F | Enable Operation |
| 目标速度 | 0x60FF/00 | int32 little-endian | 电机速度 (uu/s) |

### 速度单位换算
```
实际公式（已验证电机转动）：
  uu/s = deg/s × 600
  例：50 deg/s × 600 = 30000 uu/s

PDO格式公式（C++ 代码用的，电机不认）：
  rpm = deg/s / 6
  raw = rpm × 65536 / 0.15
```

### TCP 桥协议
```
客户端发送：TX AAAAAAAA D xx xx xx ...\n
桥回复：OK\n

客户端发送：RX\n
桥回复：AAAAAAAA D xx xx xx ...\n （或 TIMEOUT\n）

客户端发送：QUIT\n
桥回复：BYE\n
```

## 9. 已知问题

1. **C++ CAN 节点 ROS2 不可见** — fork/DDS 冲突。用 Python TCP 桥方案绕过
2. **脚底开关端口冲突** — `serial_sendCommand_node` 写死 `/dev/ttyCH341USB1`，跟力传感器冲突。需要确认开关的实际端口
3. **力传感器空载** — 力传感器测的是外骨骼受力（不是电机出力）。空载时 ~0N，需给电机加载荷才能看到力曲线
4. **can_ankleControl_node.cpp 受损** — `rclcpp::init` 缺失、所有订阅被删。框架可用但需要修复后才能跑
5. **PDO vs SDO** — C++ 代码用 PDO COB-ID (0x353) 发速度，电机只认标准 SDO (0x60FF)
6. **sendMSG 40步配置** — 旧电机固件的 PDO 映射配置，不适用当前电机，初始化花 8 秒
