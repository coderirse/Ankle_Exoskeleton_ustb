## 2. 架构（ROS2 双进程）

```
进程1(独立,sudo): can_bridge_final.py ── TCP :9876 ── 进程2(用户): ROS2控制器
       │                                                      │
  python-can CANalyst-II                                 ros2_switch.py
       │                                              订阅 /command_topic
     电机                                           发布 /target_torque /motor_speed

进程3(Python ROS2): switch_v3.py — 读 ttyACM0 发布 /command_topic
进程4(C++ ROS2): serial_encoder_node, serial_ForceSensor_node
```

**关键规则**：
- CAN 通信和 ROS2 绝不能在同一进程（fork/subprocess 破坏 DDS）
- killall python3 会杀 ROS2 守护进程，必须 ros2 daemon stop/start 恢复
- 每次启动前先拔插 ST-LINK 重置 STM32，否则 30 秒后串口出垃圾

## 4. 脚底开关

STM32F103C8T6, 固件已烧录。USART1 9600 8N1，单字节 0x41-0x44：
- 0x41: 后跟踩 → TORQUE_MODE
- 0x42: 全掌踩 → PRE_TORQUE
- 0x43: 后跟离 → TORQUE_DRIVE（助力）
- 0x44: 脚尖离 → SWING（摆动归位）

**已知问题**：上电约 30 秒后 UART 数据变垃圾（可能是 HSI 时钟漂移）。临时方案：每次测试前拔插 ST-LINK。

---

## 5. CAN 协议

- Node: 0x53, SDO TX: 0x653
- 电机使能: 0x6060=3 (PV模式), 0x6040: 6→7→0xF
- 速度指令: 0x60FF, uu/s = deg/s × 600
