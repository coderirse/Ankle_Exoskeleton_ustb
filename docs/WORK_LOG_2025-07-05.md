## 2. 架构（最终方案：TCP 桥 + ROS2 双进程）

```
┌─────────────────────────────────────────────────────┐
│  进程1: can_bridge_final.py (sudo)                   │
│  - python-can canalystii → CAN 总线                  │
│  - TCP server localhost:9876                        │
│  - 每个客户端连接时重置 CAN 状态                      │
│  - 协议: "TX AAAAAAAA D xx...\n" → "OK\n"            │
│          "RX\n" → "AAAAAAAA D xx...\n" / "TIMEOUT\n" │
└──────────────┬──────────────────────────────────────┘
               │ TCP
┌──────────────▼──────────────────────────────────────┐
│  进程2: ros2_final.py (用户态, 无sudo)               │
│  - ROS2 Node "assist_controller"                    │
│  - 订阅: /command_topic, /angle, /Force             │
│  - 发布: /target_torque, /motor_speed, /force_scaled│
│  - 自动步态循环 + 余弦助力曲线 + 摆动反转            │
│  - 通过 TCP 桥发送 CAN 命令 (SDO to 0x653)          │
└─────────────────────────────────────────────────────┘
```

**关键发现：**
- `fork()`/`subprocess.Popen` 会破坏 DDS 中间件，导致 ROS2 topic 不可见
- **解决方案：CAN 通信和 ROS2 必须分到两个独立进程**
- TCP socket 是最简单的桥接方式
- 每个 TCP 客户端连接时，桥必须创建全新的 CAN 连接（不能复用长连接）
- 力传感器测的是外骨骼受力，空载时接近 0N

## 5. 已知问题

1. **C++ 控制节点 ROS2 topic 不可见** — `fork()`/`posix_spawn` 破坏 DDS。TCP 桥双进程方案解决了这个问题
2. **力传感器空载** — 力传感器测的是外骨骼受力，不是电机出力。需要给电机加载荷才能看到力曲线
3. **can_ankleControl_node.cpp** — 编译通过但缺少 `rclcpp::shutdown()`
4. **PDO vs SDO** — C++ 代码用 PDO COB-ID (0x353)，电机只认 SDO (0x653)。TCP 桥已做翻译
5. **sendMSG 40步配置** — 不适用于当前电机，占 8 秒启动时间
