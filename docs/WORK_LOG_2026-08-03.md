### 初始化流程重构（`runInitialAlignment()`）
原逻辑：开机直接预紧到 `|force| ≥ preload_force` 即进主循环。
新逻辑：
1. **力控闭环维持 0.5~2.0 kg**：线松收线、线紧放线（跟随脚放平自动调整）
2. **四项条件同时满足并持续 2 秒** → 初始化完成并打印：
   - 开关闭合（`0x42`，双脚踩地）
   - 力在 0.5~2.0 kg
   - 编码器在 `level_encoder_target ± level_encoder_limit`
   - IMU 俯仰角 `|pitch| ≤ 15°`（无 IMU 数据告警一次并跳过）
3. 每 0.5 s 打印各条件状态，便于现场定位卡在哪一项
4. 总超时 30 s，超时告警后继续运行

**实测标定值**：假肢静止站立时编码器 **-22.14°** → `level_encoder_target=-22.14`。

### 35 kg 急停硬限值
- `torqueCallback()` 最高优先级：`|force| ≥ force_emergency`（默认 35 kg）→ 立即零速 + `STAND_MODE` + `emergency_stop` 锁存
- 主循环最前面急停分支：锁存后状态机全部失效只发零速，**必须重启节点恢复**（防鲍登线绷断后自动再拉）

### 助力跟不上问题修复（方案1+2）
现象：转速不够、时机滞后、完全没助力。根因：
- `max_speed=180°/s` 只占电机输出端峰值（100 rpm = 600°/s）的 30%（电机：卓誉 JRM-C8078-024BN，减速比 24，峰值扭矩 95 N·m，手册在 `~/motor/`）
- 力反馈仅 20 Hz，纯 PID 闭环带宽不足
- 0x43 才开始动作，蹬地前无线预张紧

修复：
1. `max_speed` → **600°/s**
2. **前馈+PID 复合控制**：`velocity = FF_GAIN×目标扭矩 + PID修正`，前馈不依赖力反馈，零滞后（`ff_gain=15`，峰值 23 Nm 时前馈 ≈345°/s）
3. **0x41 预张紧**：脚跟着地即以 `pretension_speed=60°/s` 收线至 2 kg，蹬地时线已绷紧

**改完未实测**，明天首要验证。

### STM32 心跳固件（解决初始化超时）
问题：原固件只在开关状态**变化时**发送一次。若假肢在节点启动前已站立，0x42 早已发过，控制节点永远等不到 → 初始化 30 s 超时。

方案：
- 新固件 [`User/main_heartbeat.c`](src/stm_switch/足底双开关/User/main_heartbeat.c)：状态变化立即发送 + **每 ~50 ms 心跳重发当前状态**；纯寄存器实现自带向量表，arm-none-eabi-gcc + `link.ld` 编译（524 字节）
- `serial_sendCommand_node`：重复字节去重（心跳不进步态序列）；新增 **`/switch_state`** 话题发布开关原始状态
- `can_ankleControl_node`：站立确认改订阅 `/switch_state`，步态逻辑不变
- 旧固件已备份（st-flash read）；LED 修正为低电平点亮（踩下亮）

烧录命令：
```bash
arm-none-eabi-gcc -mcpu=cortex-m3 -mthumb -O2 -nostdlib \
  -T src/stm_switch/足底双开关/link.ld \
  src/stm_switch/足底双开关/User/main_heartbeat.c -o main_heartbeat.elf
arm-none-eabi-objcopy -O binary main_heartbeat.elf main_heartbeat.bin
st-flash --reset write main_heartbeat.bin 0x8000000
```

**注意**：ST-LINK NRST 未连接，烧录后芯片不会自动重启，**需拔插一次 STM32 USB 线**新固件才运行。验证：重启后串口每 ~50ms 应有一个字节。
